# B-7（🔵）：PDF・スクショ→OCR→Excel化（ローカルPython併用でトークン節約）

**課題**：紙やPDFに閉じた数百ページの表を、手で打ち直してExcel化するのが重労働

**やること**：紙やPDFに閉じた表データを、重いOCR・表抽出はローカルPython、項目名のゆらぎ補正やOCR崩れ検出はClaudeに役割分担してExcel化。何百ページも直接読ませてトークンが膨らむのを防ぐ。

## 📋 コピペするプロンプト（Claude Code に貼る）

```text
invoices_pdf/ にある請求書PDF約200枚を、Excel取り込み用のCSVに構造化したい。
トークン節約のため、機械的な抽出はローカルのPythonで完結させ、あなた(Claude Code)は判断が要る部分だけ担当してください。

- 役割分担:
  - 【ローカルPython側】PDFからの表抽出(pdfplumber/camelot)とOCR(pytesseract)を行うスクリプトを書いて、まずローカルで一括実行。
    抽出結果を raw_extracted.csv に吐く。この処理で全PDFをあなたに直接読ませない(コスト爆発を防ぐ)
  - 【Claude Code側】raw_extracted.csv だけを受け取り、以下の「判断」を担当:
    ・項目名のゆらぎを統一(「合計」「税込合計」「ご請求金額」→「請求金額(税込)」)
    ・OCR崩れで数字が欠けた/化けた行を検出して [要確認] フラグ
    ・日付フォーマットの統一(YYYY-MM-DD)
- 金額は円表記。「+」やM/k略記は使わない
- 出力: 整形済み invoices.csv(発行日/請求元/金額(税込)/請求番号/確度/元ファイル名) + 要確認一覧
- まず処理設計(どこをPython、どこをあなたがやるか)を提示してから着手して
```

**ひとこと**：「重い機械処理はローカル、判断だけClaude」が鉄則。読み取れなかったセルは断定させず必ず `[要確認]` に回して人間が見る。
