# 事例37（🟠）：複数チャネルに散った接点から、候補を並列で漏れなく名寄せ

**課題**：案内したい相手がメール・Slack・名刺に散らばり、誰に声をかけたか毎回抜け漏れる

**やること**：献本・案内したい相手をGmail/Slack/Discord/tldv/名刺に散った接点から漏れなく拾いたい → データ源ごとに並列串刺し検索し名寄せ。

## 📋 コピペするプロンプト（Claude Code に貼る）

```text
献本先の候補を、過去の全コミュニケーション履歴から発掘して。
- 条件: 出版・メディア・教育関係者、または過去に弊社と前向きなやりとりがあった方
- 検索対象: Gmail / Slack / Discord / tldv / convo-search DB / 名刺データ
- 各データ源を20体並列で串刺し検索、該当人物を抽出
- 同一人物の名寄せをして、関係性（直近接触/過去接触/紹介経由）でスコアリング
- 各候補に「接点の内容 / 献本理由 / 連絡先」を付ける
出力: kenpon_list.md（関係性の強い順）
※ 連絡先は併記、送信はしない
```

**ひとこと**：データ源ごとに並列分担で取りこぼし防止。名寄せを明示指示し、連絡先は載せても送信はさせない（外部送信は2段階承認）。
