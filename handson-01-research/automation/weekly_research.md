# 自動実行の設計メモ（Step4・"作るだけ"）

> このハンズオンの Step4 では、リサーチを**毎週自動更新する仕組みを「設計する」ところまで**やります。
> 実際に常駐させる（cron/launchdに登録して動かし続ける）のは、環境差で詰まりやすいので**持ち帰り**にします。
> ＝「作る＝全員」「回す＝家で」。

Claude にこのファイルへ下記3点を書いてもらいます。

---

## ① スキル化の下書き（このリサーチを1コマンドに）

毎回同じ手順（5社を読む→比較表→空白地帯→HTML化）を打つのは面倒なので、
`research-competitors` という1つのスキルにまとめる。SKILL.md の骨子：

```
---
name: research-competitors
description: input/companies/ の各社プロファイルを並列で読み、比較表・空白地帯・HTMLダッシュボードを output/ に生成する
---

手順：
1. input/companies/ の各社を、サブエージェント（Haiku・読み取り専用）で並列に要約
2. 5観点（価格/機能/ターゲット/強み/弱み）をそろえて比較表に統合
3. 空白地帯を3点提案
4. templates/dashboard_template.html に流し込み output/index.html を生成

ルール：
- プロファイルにない数値・固有名詞は創作しない（「記載なし」と書く）
- 1社1サブエージェント。読み取り専用なので安全＆安い
```

## ② 定期実行のひな型（cron 1行・持ち帰り）

毎週月曜 朝9時すぎに自動でリサーチを回す例（実行は家で）。

```bash
# 毎週月曜 9:07 に competitors リサーチを実行（時刻は :00 を避ける）
7 9 * * 1  cd ~/Desktop/cc-handson/jissen-handson-0524/handson-01-research && claude -p "/research-competitors を実行して output/ を更新して" >> ~/research.log 2>&1
```

## ③ 暴走を止める安全弁（必ずセット）

自動で回す前に、上限と停止条件を必ず仕込む。

- **回数上限**：1回の実行で読むファイルは5社ぶんに限定（無限にWeb検索へ広げない）
- **コスト上限**：サブエージェントはHaiku指定。重い推論モデルを並列で使わない
- **失敗時の通知**：cronがコケたらログに残す（`>> ~/research.log`）。静かに止まるのを防ぐ
- **不可逆操作なし**：このリサーチは読み取り＋output/への書き出しだけ。削除・送信はしない

---

> 本番でWeb検索版に差し替える場合も、この3点（スキル化／定期実行／安全弁）はそのまま使えます。
